# נושמות השראה

מודול משחק קלפים קבוצתי בתוך אתר פורצות דרך. הקוד כולל את ממשקי המשתתפת, המדריכה והאדמין, Edge Function, Migration ובדיקות. אין במודול מאגר נשים מומצא או קלפים המוצגים כתוכן מאושר.

**מצב מאומת — נקודת בדיקה לפני שילוב האתרים, 25.10.2026:** תשתית המשחק הוקמה ונבדקה בפרויקט Supabase הקיים באישור בעל המערכת. ה־Migration הוחל, שש הטבלאות מוגנות, האחסון פרטי ומשימת המחיקה פעילה. פונקציית המשחק הקנונית בגרסה v4 פעילה, ללא מודול fixtures זמני. עברו 16 בקשות HTTP מול השירות המנוהל, כולל בחירות מקבילות, שחזור, הרשאות והצגת PDF פרטי. מיזוגי האתרים אושרו ומבוצעים בתהליך נפרד ומתואם; הם טרם בוצעו בנקודת בדיקה זו. טרם נטען תוכן רשמי מאושר וטרם נבדקה כניסת עובדת אמיתית בדפדפן חי. פירוט ותהליך הבדיקה הידנית: [ACTIVATION.md](ACTIVATION.md).

## הפעלה למדריכה

1. התחברי לדשבורד עם החשבון הרגיל ובחרי „נושמות השראה”. במסך ניהול המשחק לחצי על כניסה דרך הדשבורד. אם החשבון עדיין מחובר, חלון האימות יחזור ללא הזנת סיסמה נוספת.
2. הזיני את מספר המשתתפות ולחצי „משחק חדש”. הכמות נקבעת לפי קבוצות התוכן השלמות; מספר אי־זוגי דורש שלישייה מאושרת.
3. הציגי את ה־QR או העתיקי את הקישור. המשתתפות מזינות שם בלבד. שמות זהים מותרים. רענון מאותו מכשיר משחזר את ההשתתפות.
4. לפני הבחירה אפשר לתקן שם, להסיר רישום או לעדכן כמות ולהגריל מחדש. הכמות לא יכולה להיות קטנה ממספר המצטרפות.
5. משתתפת ללא טלפון: הוסיפי אותה ידנית בחדר ההמתנה. לאחר פתיחת הבחירה הקצי לה מספר קלף; כפתור „הצגת קלף” מאפשר להציג עבורה את התוכן.
6. כאשר מספר הנרשמות תואם לכמות החדר, לחצי „מתחילות לבחור קלפים”. כל משתתפת בוחרת פעם אחת; השרת מאשר את הבחירה לפני הצגת הקלף.
7. לאחר שכל הקלפים נבחרו, עברי למציאת החיבורים. המשתתפות מחפשות בעצמן בכיתה את בעלות הסמל הזהה. מצב קבוצות בלוח הניהול מציין **בחירת קלפים**, ולא מציאת התאמה בכיתה.
8. המשיכי ל„מפצחות את הקוד” עם דפי העבודה הקיימים, ולאחר מכן סיימי את המשחק. סיום חוסם הצטרפות ובחירה ואינו מוחק מיד את סיכום החדר.

הבחירה הראשונה נועלת את ההקצאה והמספור. עזיבה או ניתוק אינם משנים בחירות אחרות. חיבור שלא עודכן זמן מה מסומן למדריכה. אפשר לחזור לניהול חדר דרך רשימת החדרים לאחר הזדהות.

בצורה `site:women/Amelia.png`, יחד עם שם האישה, הסמל וקבוצת ההתאמה.
קובצי התמונה עצמם אינם מועתקים אל Supabase.

בשעת הצגת כרטיס, שרת המשחק מאמת את אסימון המשתתפת/המדריכה מול ה־RPC,
ומחזיר הפניה לכתובת התמונה הסטטית באתר הקורס. מותרות רק תמונות מתוך
`https://portzot-derech.org/inspiration/cards/women/` ובשמות קבצים פשוטים ומוגדרים.
אין כתובות חופשיות, אין מעבר לתיקיות אחרות ואין שינוי בהרשאות המשחק.

**הערת פרטיות:** קובצי התמונות נמצאים במאגר GitHub ציבורי ובאתר ציבורי ולכן
עצם ידיעת כתובת התמונה מאפשרת צפייה בה גם ללא כניסה למשחק.
המשחק עדיין לא חושף למשתתפות את מפת ההתאמות, בעלות קלפים אחרים או
פרטים אישיים. אם בעתיד יידרשו תמונות פרטיות, יש לעבור לאחסון פרטי.

קישורי התמונות דורשים החלה חד־פעמית של Migration
`20261025123000_inspiration_site_card_links.sql` ועדכון פונקציית
`inspiration-game`. לא נדרשת העלאת קובצי התמונות או יצירת bucket נוסף.

הזוגות, השלישייה והסמלים עדיין דורשים שיוך לפי הרשימה המאושרת.
אין להסיק קבוצות התאמה מתוך שמות הקבצים.

## טעינת תוכן מאושר

1. ודאי שהאחסון הפרטי הוכן כמתואר בהמשך והיכנסי כאדמין למאגר הקלפים.
2. צרי קבוצת התאמה מושבתת: סמל מאושר וגודל 2 או 3. המערכת מאפשרת שלישייה פעילה אחת בלבד וסמל פעיל ייחודי לכל קבוצה.
3. הוסיפי את הנשים והעלי לכל קלף לפחות תמונה או PDF אחד. נתמכים PNG, JPEG, WebP ו־PDF עד 12 MiB, צד קדמי ו/או אחורי. העלאה מקבלת נתיב חדש; אין החלפה של קובץ המשמש חדר קיים.
4. הפעילי את הקלפים ואת הקבוצה רק לאחר השלמת התוכן המאושר. קבוצה פעילה חייבת להכיל בדיוק שניים או שלושה קלפים פעילים וכל הקבצים חייבים להתקיים באחסון פרטי.
5. הפעילי בדיקת תקינות. שמות נשים פעילות אינם יכולים לחזור על עצמם לאחר הסרת רווחים מיותרים והתעלמות מהבדלי אותיות גדולות.

אפשר לייבא JSON עם `groups` ובכל קבוצה `cards`. אפשר להשמיט `id` ליצירה חדשה; לעדכון יש להשתמש ב־UUID הקיים. שדות קלף: `woman_name`, `field`, `front_path`, `back_path`, `active`. שדות קבוצה: `id`, `symbol`, `size`, `active`, `cards`.

CSV מכיל שורה לכל קלף, עם הכותרות `group_id,symbol,size,name,field,front_path,back_path,active`. `group_id` הוא UUID; `id` של הקלף אופציונלי. עמודת `group_active` אופציונלית ומאפשרת לייבא טיוטות (`false`). ברירת המחדל ב־CSV היא קבוצה וקלפים פעילים, ולכן יש להעלות מראש קבצים תקינים ולייבא קבוצות שלמות. נתמכים שדות מצוטטים, פסיקים, מרכאות כפולות וירידות שורה בתוך שדה.

היבוא מעדכן רק רשומות שסופקו; הוא אינו מוחק רשומות חסרות. כדי להשבית קלף קיים, עדכני אותו ל־`active:false`. שיוך קלף קיים לקבוצה קבוע: להתאמה חדשה יוצרים רשומה חדשה ומשביתים את הקודמת. חדרים שכבר נוצרו שומרים תמונת מצב של הקלפים, ההתאמות ונתיבי הקבצים.

## מיפוי התשתית וההזדהות

- אתר הקורס סטטי ומשתמש ב־Service Worker ובשרת Node לפיתוח/יצוא PDF. החיבור הקיים לפרויקט `lmccphquxksnyvhfgsiw` נשאר ללא שינוי.
- המשחק מתחבר באופן ממוקד לפרויקט הדשבורד `szinlhjuwyiyszdpsdop`, באמצעות מפתח publishable. אין מפתח שרת בקוד הדפדפן.
- נבדקו `frontend/src/api.js`, `frontend/src/supabase-client.js`, הרשאות ואזור המדריכות בדשבורד. זהות עובד נקשרת ל־`public.users.auth_user_id`, וההרשאה דורשת משתמש פעיל, שיוך חד־משמעי ותפקיד `instructor` / `admin`, או הרשאה מפורשת `permissions.inspiration_manage:true`. רק `admin` מנהל תוכן.
- דומיין הקורס הוא `portzot-derech.org`, והדשבורד נמצא תחת `taasiyeda2026.github.io`. לכן המעבר משתמש בחלון אימות ו־`postMessage` עם בדיקות מקור מדויק, חלון מקור ו־nonce. אסימונים אינם עוברים בכתובת.
- הדשבורד שולח **access token בלבד** לאחר אימות `getUser`. המשחק שומר אותו ב־sessionStorage של הכרטיסייה. הדשבורד לבדו מנהל refresh token, כדי למנוע התנגשות בחידוש התחברות בין שני האתרים. `getUser` בצד השרת מאמת כל פעולת ניהול; מידע מקומי אינו מעניק הרשאה.
- משתתפת מקבלת אסימון חדר אישי שאינו Supabase Auth ואינו מחליף את התחברות המדריכה. מזהה ניסיון הצטרפות אקראי מאפשר שחזור לאחר תשובה שאבדה. השרת שומר גיבובי אסימונים בלבד; האסימון נגזר מסוד חדר אקראי ומוגבל לחדר ולמשך חייו.
- המשחק הקיים `p.nativ/game`, שותפה לדרך ועורך הפוסטרים לא שונו. ה־Service Worker בגרסה `v184` מדלג על כל `inspiration/` ועל בקשות Supabase; אין מטמון של נתוני חדרים, פרטי התחברות או קלפים פרטיים.

## מסד ו־API

Migration: `supabase/migrations/20261024181538_inspiration_game.sql`, **לפרויקט הדשבורד בלבד**. מוסיף:

- `inspiration_match_groups`, `inspiration_cards`: מאגר תוכן וסטטוס הפעלה.
- `inspiration_rooms`: בעלות, קוד אקראי, שלב, תוקף, ערוץ עדכון וסוד השתתפות.
- `inspiration_room_players`: שמות מינימליים, מזהים, גיבובים וזמן קשר אחרון.
- `inspiration_room_cards`: תמונת מצב, מספר קבוע, בחירה ואילוצי ייחודיות/FK.
- `inspiration_room_events`: תיעוד פעולות ניהול ללא שמות ואסימוני תלמידות.
- `inspiration_private`: פונקציות עזר, הגבלת קצב ומחיקה תקופתית.

כל הטבלאות הציבוריות מפעילות RLS ואין ל־`anon` או `authenticated` גישה ישירה אליהן. שתי פונקציות ציבוריות מותרות ל־`service_role` בלבד: `inspiration_rpc` ו־`inspiration_rate_limit`. ה־Edge Function מאמת את חשבון העובדת, והמסד בודק תפקיד ובעלות. פעולת בחירה נועלת חדר בטרנזקציה, מוודאת שלב ומקצה קלף רק אם הוא פנוי. אילוצי המסד מבטיחים משתתפת אחת לכל קלף וקלף אחד לכל משתתפת באותו חדר.

Edge Function: `supabase/functions/inspiration-game/`. אימות JWT של הפלטפורמה מבוטל **לפונקציה זו בלבד**, כי המשתתפות משתמשות באסימוני השתתפות נפרדים; כל נתיבי הניהול מאמתים Supabase JWT בעצמם באמצעות `getUser`.

השרת מגיש למשתתפת רק את הקלף שלה ואת מספרי הקלפים התפוסים. תוכן מדיה מוזרם אחרי אימות הבעלות, עם `no-store` וללא נתיב קובץ בתשובה. האחסון חייב להיות פרטי גם בעת ההצגה. PDF מוצג ב־PDF.js על canvas; אין כפתורי הורדה/הדפסה. צילום מסך או העתקה של תוכן שכבר הוצג אינם נחסמים באופן מוחלט.

Realtime משדר הודעת שינוי בלבד בערוץ אקראי שאינו מכיל שמות, מפה או קלפים. ההודעה מפעילה קריאה מאומתת למצב השרת, ולכן אינה מקור סמכות. יש גיבוי בקצב 15 שניות, backoff עד 60 שניות, השהיה לכרטיסייה מוסתרת ושחזור בחזרה לחיבור. הגבלת קצב הבקשות הציבוריות מתבצעת בטרנזקציה נפרדת, כך שגם בקשות שנדחות נספרות; נשמר גיבוב כתובת רשת בלבד.

## תשתית שהופעלה ובדיקת השילוב

הפעולות הבאות כבר בוצעו בפרויקט הקיים `szinlhjuwyiyszdpsdop` באישור בעל המערכת:

1. ה־Migration בשם `inspiration_game` הוחל ונרשם בהיסטוריית Supabase בגרסה `20261024230248`. אומתו RLS ו־REVOKE על שש הטבלאות ועל מונה האירועים; רכיבי המערכת הקיימת נשמרו.
2. bucket פרטי בשם `inspiration-cards` פעיל, עם מגבלת 12 MiB ו־PNG/JPEG/WebP/PDF. הקוד הקנוני של `inspiration-game` פעיל בגרסה v4, ללא מודול אתחול fixtures זמני. תגובת `401` לבקשת חימום בלתי מזוהה היא התנהגות צפויה.
3. משימת `inspiration-retention` פעילה עם לוח זמנים `15 2 * * *` ב־UTC. שמות, אסימונים ותיעוד החדר נמחקים 30 יום לאחר סיום/תפוגה; מוני בקשות ישנים נמחקים לאחר יום. שמונה משימות cron המקוריות נשמרו ללא שינוי; משימה נוספת שאינה קשורה למשחק נוצרה בנפרד.
4. עברו 16 בקשות HTTP אמיתיות דרך `pg_net`, כולל תחרות על קלף אחד, שחזור השתתפות, חסימת אסימונים מזויפים, PDF פרטי וסיום חדר. שני סטי נתוני הבדיקה הזמניים נמחקו ומחיקתם אומתה. נשמר בכוונה PDF פרטי המסומן `TEST ONLY`, ונוצר חדר בדיקה נפרד לשתי משתתפות בתוקף שמונה שעות, בבעלות חשבון אדמין קיים. אלו אינם תוכן מאושר ואינם חלק ממאגר הקלפים הרשמי. קישור החדר נמסר בנפרד ואינו נשמר בתיעוד הציבורי.

לאחר השלמת השילוב המתואם בשני האתרים יש לבצע את [הבדיקה הידנית בשני דפדפנים או מכשירים](ACTIVATION.md#manual-live-check): כניסת מדריכה בחשבון הקיים, הצטרפות לחדר הבדיקה שנמסר או יצירת חדר לאחר טעינת תוכן מאושר, בחירה, ניתוק וחזרה וסיום. לא נוצרו או שונו חשבונות עובדים לצורך הבדיקות. הפעלה בכיתה מותנית גם בטעינת התוכן המאושר ובבדיקת מכשירי iOS/Android אמיתיים.

הכלי `node inspiration/scripts/setup-storage.mjs --check` נשאר בדיקת קריאה בלבד כברירת מחדל; `--apply` וכל שינוי תפעולי נוסף מחייבים הרשאה מתאימה. מקור ה־CORS מוגבל לדומייני הייצור; פיתוח מקומי דורש opt-in מדויק. פרטי ההפעלה והמגבלות העדכניות מתועדים ב־[ACTIVATION.md](ACTIVATION.md) וב־[QA.md](QA.md).

חזרה לאחור: הסירי את הכניסות למשחק והחזירי את גרסת הקוד הקודמת בשני האתרים באמצעות revert מתועד. סקריפט `sql/disable-game.sql` משבית רק את הרשאות שרת המשחק ואת משימת המחיקה שלו; `sql/restore-game.sql` מחזיר אותן. הסקריפטים אינם מוחקים טבלאות, קבצים או נתונים ואינם משנים Auth. מחיקת מידע/קבצים דורשת תהליך נפרד ומאושר.

## בדיקות חוזרות

נבדק עם Node 24, Chromium 154 ו־PostgreSQL 17 ב־Docker. כל הדגימות נוצרות בבדיקות בלבד ולא נכללות במאגר התוכן הרשמי.

```sh
npm ci
npm ci --prefix inspiration
npm ci --prefix inspiration/tests
npm test
npm run test:inspiration:db
```

לבדיקת דפדפן מלאה משתמשים במסד בדיקות זמני שהבדיקה מקימה, ולא בכתובת Supabase:

```sh
INSPIRATION_DB_FIXTURE=/tmp/inspiration-fixture.json npm run test:inspiration:db
INSPIRATION_DB_FIXTURE=/tmp/inspiration-fixture.json npm run test:inspiration:browser
```

הקובץ מכיל פרטי חיבור ל־loopback בלבד ושם container לבדיקה. לאחר הבדיקה יש לעצור את ה־container המופיע בו; ללא משתנה זה בדיקת המסד מנקה את ה־container בעצמה. בדיקת הדפדפן מסרבת למסד שאינו מקומי ואינה שולחת בקשות לייצור. אפשר להגדיר `CHROMIUM_PATH`; ברירת המחדל `/usr/bin/chromium`.

הספריות המקומיות מוצמדות לגרסאות ומצורפים lockfiles ורישיונות. לעדכון נכסים יש להריץ `npm run vendor --prefix inspiration` אחרי שינוי מכוון של הגרסאות. פרטי האימות ותוצאות הבדיקות: [QA.md](QA.md).
